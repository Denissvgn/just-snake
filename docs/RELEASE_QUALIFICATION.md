# Candidate qualification and independent review

Use native ARM64 Node 24 and both exact dependency locks. Install legacy dependencies with `PUPPETEER_SKIP_DOWNLOAD=true npm ci --prefix tests`; legacy tests use the pinned native Playwright Chromium executable, never a downloaded Linux x86 Chrome-for-Testing binary.

`npm run qualify -- --phase prepare --output <new-candidate-directory>` freezes checked inputs and builds once. `--phase check --candidate <directory>` verifies input and payload hashes plus the dist allowlist/budgets. `--phase test --candidate <directory> --group infrastructure|static|legacy|release --output <new-report-directory>` runs real suites and checks drift before/after. An optional `--engines chromium` or `--engines firefox,webkit` is a strict, nonempty unique subset; omission means all three. Release runs include the complete source and ordinary prefix/root spec inventories, including metadata, Auto, resize and HUD cases whose catalog type alone does not describe all their ordinary capabilities. They use the same candidate payload, copied without rebuilding into the conventional dist path for legacy-compatible artifact tests. No filtered report is a complete qualification.

`--phase assemble --candidate <directory> --reports <infrastructure,static,legacy,linux-release,mac-release-directories>` requires all 60 local acceptance IDs, all 20 static suites, all 26 legacy suites, actual per-case source/ordinary prefix/ordinary root coverage in every required engine, logical/measurement source cases in every engine, no failures/skips/timeouts, and matching actual input/payload identities. It produces `review_pending` with `localQualified:false`; successful CI does not impersonate independent review.

The independent reviewer inspects the full real results and creates `.github/release-attestation.json`, embedding the sanitized complete report, actual verdict and identities. `reportSha256` hashes recursively key-sorted embedded report JSON (arrays retain order). The record is authenticated procedurally through trusted repository publication and protections, not cryptographic proof of agent independence. No key, secret, repository variable or manual bootstrap is required, and an implementer-generated accepted fixture is never the real review. The independent reviewer owns the real record. Hosted jobs validate all of its required coverage and matching byte identities, then independently execute the full hosted suites. PR jobs remain read-only and cannot deploy; deployment uses only the trusted discovered default or explicitly authorized dispatch revision.

The checked-input map includes canonical source/assets, current `.mjs` tooling, tests and machine contracts in `tests/support`, root Playwright configuration, exact package metadata/locks, workflows/action pins/notices, and operational README/publishing/performance/qualification guidance. Planning documents, task DAGs, specs and historical patch recipes are absent from the public source tree and are not inputs. `.github/release-attestation.json` alone is excluded to avoid circular review identity. The attestation records the exact reviewed revision; CI/deployment separately record their public revision. A review-record-only commit is never mislabeled the tested commit: all actual checked byte maps must match, and every checked input change requires new qualification and independent review.

`--phase finalize --candidate <directory> --attestation <file>` validates the complete independent record and reviewed identity, and retains the attestation with the candidate. Hosted CI must additionally pass its own full current suites. No default `localQualified:true`, local fixture flag or missing engine can authorize deployment. Only an actual independent review may create the final attestation; test fixtures never authorize deployment. The machine schema is [tests/support/release-attestation.schema.json](../tests/support/release-attestation.schema.json).

Retained candidates contain only `dist/**`, candidate identity, qualification report and attestation in a validated regular-file tar.gz. Rollback rejects traversal, absolute/dot/duplicate paths, links/special files, excess size, bad checksums or provenance before extraction. A verified successful deployment record and unexpired trusted artifact identity are required; uploading an artifact alone never makes it known-good live. Re-upload the checked old dist as a new Pages artifact in the current authorized rollback run. Retention is min(30, actual discovered repository maximum).

`npm run qualify` with no options runs a unique fresh invocation: prepare/check, full infrastructure, static, legacy, all-three-engine source and ordinary prefix/root inventories, assembly, then matching actual independent attestation finalization. Missing or mismatched `.github/release-attestation.json` returns nonzero and preserves the pending assembled report; it never changes pending evidence into approval. Full mode rejects engine subsets. Explicit `--phase` CI commands retain their narrower semantics. Installs remain separate prerequisites.

`npm run verify:live -- --url <discovered-site-directory-url>` resolves `.artifacts/qualification/latest.json` from the last full invocation and validates that actual candidate's current input/payload identity before any network request. An optional `--manifest <candidate-or-report.json>` selects explicit expected bytes; positional URL/manifest compatibility remains available for workflow commands. Missing/stale default references fail, with no invented manifest or site.

Before a release matrix, the qualifier performs a real selected-engine capability preflight against the frozen candidate. It validates live WebGL2 shader draw/readback, a nonblank actual game framebuffer, completed game rendering and a native movement run, with strict error/request guards and candidate identity checks. Hosted Chromium and WebKit run on native ARM64 macOS; Chromium uses the same ANGLE Metal arguments in functional tests and preflight, with the actual Metal backend verified. Firefox runs on native ARM64 Linux with the same headed Xvfb/Mesa llvmpipe profile in functional tests and preflight, inside one owned native PulseAudio server with a private Unix socket and real system-clocked null sink. The Linux backend proof binds current candidate inputs/payload and full source/prefix/root results, retains a real Firefox stream witness, and verifies cleanup before assembly. Sampling stays bounded throughout the job; the runner shares its recorded 120-minute job deadline with cleanup/upload reserve. This verifies software audio lifecycle, not physical sound output. Local native macOS Firefox remains supported. The default semantic viewport is 1000×700, while explicit responsive and rendering profiles remain unchanged. Continuous trace screenshots are disabled; per-case PNGs and DOM/action/network/source traces remain. A failed hosted partition stops further partitions, preserves incomplete evidence and cannot assemble or deploy.

The catalog has 62 total IDs, including two publication-only gates. Eight `ACC-PRES` cases additionally require actual observed Original/Neon coverage for their declared engine/target combinations; unrelated cases keep their existing scope. Completed scene/UI observations and their digests flow through Playwright reporting and assembly. Missing, stale, forged labels and filtered reports cannot supply mode coverage. The two-ID resource case shares one 100-cycle run with the existing resource gate.

Before a long matrix, prepare/check a unique provisional candidate and run the exact `npm run verify:live -- --url http://127.0.0.1:<owned-port>/just-snake/ --manifest <candidate>/candidate.json` against its immutable dist. Omit `--record` for local smoke. It verifies exact served bytes, decoded local art/font/module and native Start → Score 10 → summary → restart in both appearances at root and alias. Repeat on final bytes if checked inputs changed. Keep independent review as the final phase: prepare/check/test/assemble, reviewer attestation, then finalize.

Recovery retains a narrowly pinned compatibility contract for the previously reviewed Original-only release. Its complete input-map digest, source, payload and contract must match [the machine record](../tests/support/original-release-contract.json), followed by the ordinary trusted artifact, attestation, expiry and byte checks. This historical profile permits its implicit Original render semantics; current candidates always require declared completed renders of both appearances. A missing module or a requested mode that fell back to Original never qualifies a current Neon smoke.
