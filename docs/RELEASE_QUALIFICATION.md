# Candidate qualification and independent review

Use native ARM64 Node 24 and both exact dependency locks. Install legacy dependencies with `PUPPETEER_SKIP_DOWNLOAD=true npm ci --prefix tests`; legacy tests use the pinned native Playwright Chromium executable, never a downloaded Linux x86 Chrome-for-Testing binary.

`npm run qualify -- --phase prepare --output <new-candidate-directory>` freezes checked inputs and builds once. `--phase check --candidate <directory>` verifies input and payload hashes plus the dist allowlist/budgets. `--phase test --candidate <directory> --group infrastructure|static|legacy|release --output <new-report-directory>` runs real suites and checks drift before/after. An optional `--engines chromium,firefox` or `--engines webkit` is a strict, nonempty unique subset; omission means all three. Release runs include the complete source and ordinary prefix/root spec inventories, including metadata, Auto, resize and HUD cases whose catalog type alone does not describe all their ordinary capabilities. They use the same candidate payload, copied without rebuilding into the conventional dist path for legacy-compatible artifact tests. No filtered report is a complete qualification.

`--phase assemble --candidate <directory> --reports <infrastructure,static,legacy,linux-release,mac-release-directories>` requires all 52 local acceptance IDs, all 20 static suites, all 26 legacy suites, actual per-case source/ordinary prefix/ordinary root coverage in every required engine, logical/measurement source cases in every engine, no failures/skips/timeouts, and matching actual input/payload identities. It produces `review_pending` with `localQualified:false`; successful CI does not impersonate independent review.

The independent E04 reviewer inspects the full real results and creates `.github/release-attestation.json`, embedding the sanitized complete report, actual verdict and identities. `reportSha256` hashes recursively key-sorted embedded report JSON (arrays retain order). The record is authenticated procedurally through trusted repository publication and protections, not cryptographic proof of agent independence. No key, secret, repository variable or manual bootstrap is required, and an implementer-generated accepted fixture is never the real review. E04 owns the real record. Hosted jobs validate all of its required coverage and matching byte identities, then independently execute the full hosted suites. PR jobs remain read-only and cannot deploy; deployment uses only the trusted discovered default or explicitly authorized dispatch revision.

The checked-input map includes canonical source, assets, current .mjs scripts, the required plan validator and tests (excluding installed dependencies/debug fixtures), both locks, package metadata, workflows/action pins, notices, attestation schema and the exact public historical/performance/qualification docs consumed by DOC01 (ENHANCEMENTS, SPEC files, HISTORICAL_RECIPES and tests README). Only `.github/release-attestation.json` is excluded to avoid circular review identity. The acceptance catalog and structural manifest/schema/id are included; only per-task status is normalized away. Unrelated legacy Python patch recipes and prose-only/status edits are outside the executable input identity. The attestation records the exact reviewed revision; CI/deployment separately record their public revision. A status/attestation-only commit is never mislabeled the tested commit: unchanged byte maps must match, and every executable/workflow/input change requires new checks and independent review.

`--phase finalize --candidate <directory> --attestation <file>` validates the complete independent record and reviewed identity, and retains the attestation with the candidate. Hosted CI must additionally pass its own full current suites. No default `localQualified:true`, local fixture flag or missing engine can authorize deployment. Real final attestation belongs to E04; E02 ships only this procedure/schema and executable rejection tests.

Retained candidates contain only `dist/**`, candidate identity, qualification report and attestation in a validated regular-file tar.gz. Rollback rejects traversal, absolute/dot/duplicate paths, links/special files, excess size, bad checksums or provenance before extraction. A verified successful deployment record and unexpired trusted artifact identity are required; uploading an artifact alone never makes it known-good live. Re-upload the checked old dist as a new Pages artifact in the current authorized rollback run. Retention is min(30, actual discovered repository maximum).

`npm run qualify` with no options runs a unique fresh invocation: prepare/check, full infrastructure, static, legacy, all-three-engine source and ordinary prefix/root inventories, assembly, then matching actual independent attestation finalization. Missing or mismatched `.github/release-attestation.json` returns nonzero and preserves the pending assembled report; it never changes pending evidence into approval. Full mode rejects engine subsets. Explicit `--phase` CI commands retain their narrower semantics. Installs remain separate prerequisites.

`npm run verify:live -- --url <discovered-site-directory-url>` resolves `.artifacts/qualification/latest.json` from the last full invocation and validates that actual candidate's current input/payload identity before any network request. An optional `--manifest <candidate-or-report.json>` selects explicit expected bytes; positional URL/manifest compatibility remains available for workflow commands. Missing/stale default references fail, with no invented manifest or site.
